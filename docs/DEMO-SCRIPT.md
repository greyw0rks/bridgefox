# BridgeFox demo script

This script accompanies an actual browser walkthrough. The requested KittenTTS 2 voice track is synthesized from the participant’s saved voice reference. It is a draft, and is not evidence of a participant recording their own narration. The event checklist’s narration restriction still needs official confirmation.

1. **Introduction.** This is BridgeFox, a compatibility studio for bringing Chrome extensions to Firefox. The idea is simple: developers should be able to understand what needs to change, review those changes, and test the result. BridgeFox brings that process into one workspace, with the developer making the final decision.
2. **Import.** I’m starting with Tab Pocket, an original example extension that saves a page and lets you reopen it later. BridgeFox accepts extension source ZIPs and public GitHub branches. It preserves the source, assets, and licenses, then checks the manifest and JavaScript against bundled Mozilla compatibility data.
3. **Compatibility.** The report identifies the Manifest V3 background service worker as a migration concern. You can inspect API compatibility and permissions separately. Compatible Chrome API calls stay in place. Unsupported features and unknown behavior remain visible, so a compatibility score never becomes a promise that every extension will work.
4. **Migration.** For this live walkthrough I’m using local rules, which work without an AI account. The migration proposes a Firefox background script and an add-on identity. It preserves the extension’s permissions and functionality. The separate Otari workflow uses an analyst and an engineer, with two distinct open-weight Qwen models.
5. **Review.** Here is the original Chrome manifest beside the proposed Firefox source. You can search files, switch between split and unified diffs, and focus the editor. Changes are proposals for review. The pipeline rejects permission changes, unsafe paths, and attempts to hide unsupported features by deleting them.
6. **Otari evidence.** This retained report records a genuine Otari migration completed on November sixth. Both models responded, and the Python sandbox validation succeeded. The known job cost was just over one cent. Web fetch was disabled for the workspace. Routing fallback and gateway-enforced limits remain unverified, and I’m not replaying a paid request for this recording.
7. **Export.** The export screen shows validation results and downloads the Firefox candidate ZIP. Extract it, open Firefox’s temporary add-on page, and select the manifest. The exact candidate from the retained Otari run passed automated save, persistence, and reopen checks in Firefox. Every extension still needs its own runtime testing.
8. **Close.** BridgeFox also preserves larger source repositories for review, including TypeScript and browser manifest templates. Those repositories must be built before installation. The goal is a clearer path from Chrome source to a tested Firefox extension, with reviewable changes and honest evidence. Chrome extensions. Firefox freedom.
